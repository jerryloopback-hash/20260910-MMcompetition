> **版本状态**：v1.1 完成（2026-09-12，复核修订）。依据 `p3_plan.md` §四 / D10 / 里程碑 M4；M3 审计两条硬约束（m3_model.md §10）为设计前提。
> 复现：`python m4_tree.py`（约 1 分钟，334 日自检 + 报告）；`import m4_tree` 供 M5 消费；独立复核 `python _m4_audit.py`。
> v1.1 相对 v1 的改动：①**SOC 偏离 D10 字面予以采纳**（附两条条件，见 §6）——连续逐场景状态 + 执行层实测根，D10 的节点条件（修正量、实测 SOC）在两层各自成立；②**补上执行重解的路由能力**：v1 代码用全池、且 `build_tree` 不暴露切分模型，文档 §3 声称的"条件场景 = 所落簇的供体子集"无法实现；现节点存下 PCA 载荷+质心，新增 `route_node()`，`build_exec_ensemble(..., cond=)` 两模式皆可跑并自检；**实测后默认取全池**（理由见 §3，硬条件在 18:00 会把晚间负载残差锁死为 0），条件臂留作 M7 消融。主数字（占用 3.0/8.6/19.3、最大叶 3.8）不变。

## 1. 定位与任务

把 M3 供体库组装成 M5 可直接消费的逐日对象：(a) 规划 LP（阶段 1 计划，扩展型）用的场景集合与决策共享结构（3×3×3 条件聚类树）；(b) 执行重解（D2 全量追索）用的逐会话条件集合。本层只做结构与集合，不求解。

## 2. 场景集合（M5 规划 LP 的输入）

按 M3 审计修正，**有效情景数 = 池宽**：场景 = 池 [max(0,e−28), e−1) 内的全部不同整日路径（≤28 条），等权 1/K；不做 N 次重抽样。逐场景：

- **整点真值路径**：$A^\omega = C_{\text{adj},0}(e) + \tilde\varepsilon_0(d') - \text{shift}$（ε0 块再中心化 → 场景均值 ≡ 采纳中心，assert）。整点层不截零以保恒等式精确；
- **十分钟真值路径**：$C_{\text{slot,adj}}(e,0) + (A^\omega - C_{\text{adj},0})\cdot P_h$（形态剖面，均值 1，截零 ≥0）——规划 LP 的物理输入；
- **负载路径**：$L_{\text{adj}}(e) + \tilde r_L(d') -$ 逐 slot 池均值（再中心化）；
- 泄漏防护：供体索引严格 < e（assert）。

## 3. 架构：规划树与执行重解分离（硬约束①的实现）

**代数事实**：情景的阶段 s 中心路径 $C_s^\omega = C_{\text{adj},0}(e) + \sum_{k\le s}\tilde G_k(d')$ 与"锚定在采纳中心的偏差参数化" $C_{\text{adj}}(e,s) + \sum_{k\le s}(\tilde G_k(d') - G_k(e))$ **逐点相等**（因 $C_{\text{adj}}(e,s) = C_{\text{adj},0}(e) + \sum_{k\le s}G_k(e)$）。故参数化选择不影响场景路径的边际分布，只影响**节点聚合**——泄漏问题只可能出在聚合层，本架构如下分离：

- **规划树**（M5 阶段 1 计划 LP 的扩展型）：节点中心 = 成员均值（未锚定）。整个树只使用池信息（供体自身的 G̃），不含当日任何实现值 → 阶段 1 计划无泄漏。阶段 1 计划 p 是 D9 要求的联合优化解：其 37–144 段形状即未来偏差罚 |q−p| 的对冲中心，由树的整体期望费用联合决定。
- **执行重解**（M5 逐会话，D2 全量追索）：根 = (C_adj(e,s), 实测 SOC)，即硬约束①"阶段 s 节点中心 = C_adj(e,s)"在结算发生处**精确成立**（assert）；残差 ε̃_s − μ_s 再中心化（信任采纳中心，与 M3 二级检验结论一致）。
  - **条件集取全池（默认）**。理由：一阶条件已经由中心 $C_{\text{adj}}(e,s)$ 承担——它本身就是当日至 $s$ 的采纳预报，已含全部已实现修正量；场景集合只决定二阶的**谱宽**。实测（`_m4_audit.py` 审计2）条件/全池谱宽比只有 6:00 = 0.91、12:00 = 0.83（18:00 = 0.42，但见下），即"用前缀去收窄残差分布"在成本相关的两个块上几乎不改变结果。
  - **硬条件臂（`cond=True`）已实现但不作默认**：`route_node()` 把当日已实现前缀 $(G_1(e),\dots,G_s(e))$ 路由到节点。实测条件集规模：6:00 中位 10（仅 2.4% 为 1）、**12:00 中位 3（15.9% 为 1）**、**18:00 中位 1（66.7% 为 1）**。18:00 的退化不是"信息足够多"，而是**供体池被切得太薄**：该块负载残差 std 达 253 kW（块均值 3989 kW），硬条件会把这份负载不确定性一并锁死为 0，导致晚间欠套保。故默认全池，硬条件留作 M7 的消融臂。
  - **未来信念 = 池律原始 G̃**（不加当日实现值，无泄漏）。

## 4. 聚类结构（硬约束②）

逐阶段**全局 PCA(top-2)** + k-means(k=3, k-means++, 固定种子)，层次嵌套：阶段 2 按 G̃1（18 维）聚 3 簇；阶段 3 在各簇内按 G̃2（12 维）聚 3；阶段 4 在各簇内按 G̃3（6 维）聚 3。聚类输入 = 池内不同整日路径（≤28），无重抽样。空簇不注册；k = min(3, 成员数)。

PCA 取 top-2 的依据（M3 §7）：主子空间 λ1/λ2 = 2.3–4.5 良态，PC1+PC2 占比 ε0 0.68 / G1 0.79 / G2 0.88 / G3 1.00；G3 近秩 1，阶段 4 聚类实际按单一方向分档。

**路由（v1.1 新增）**：每个父节点的切分模型（PCA 活维掩码、活维中心 μ、载荷 P、投影空间质心）与子映射 `child_map` 随节点保存，故任一新点（当日已实现前缀 $G_s(e)$）可按"投影→最近质心"落到该层节点上（`assign_node` / `route_node`）。这是硬条件臂的实现基础，也是文档 §3 那句"条件场景 = 所落簇"在 v1 里**无法实现**的原因——v1 的节点只存 members/n/parent，外部无路可路由。

## 6. SOC 的处理（对 D10 字面的偏离：**审计采纳，附两条条件**）

D10 / PLAN §四要求"节点非预期性同时条件在（修正量，实测 SOC），SOC 粗离散（{1200,6000,10800} 三档，与修正量聚类交叉成节点）"。本架构的实现：

- **规划树（扩展型）**：SOC 为**逐场景连续状态**——每场景的 SOC 轨迹由计划/节点决策与其自身物理（PV 充电、放电、界约束）线性推出，不截断、不作节点维度。
- **执行重解**：根 SOC = 实测值（连续、精确），D10 的"条件在实测 SOC"在结算发生处成立。

**审计裁决：采纳。** 理由与两条条件如下。

**(1) D10 的两项要求分别落在两层，各自成立，不构成对节点条件的违背。** 规划树的节点条件在**修正量**（聚类在 $G_s$），执行根条件在**实测 SOC**（精确）。被替换掉的只是"SOC 粗离散"这一**实现手段**：离散的动机是让节点能被 SOC 索引（分解式实现中状态无法连续跨块携带），而扩展型 LP 里状态本就逐场景连续携带，离散只会引入误差、不带来任何必需性。且"不分档"= 把可区分的状态合并共享决策，是**更粗的信息集**——非预期性只会更保守成立，不会违规。

**(2) 阶段 2 的分档在本题数据下近乎为空。** 0:00–6:00 的实际光伏均值仅 28.7 kW（逐日累计 172 kWh，最大 689 kWh）对 9600 kWh 的 SOC 区间；且第一阶段计划（充放电）对全场景共享，故 SOC(6:00) 逐场景近似确定 —— 按 {1200,6000,10800} 交叉出的 3 档里会有 2 档长期空置。**阶段 3/4 的 SOC 确实随上午/下午光伏实现而分散，这一点本层的论证不覆盖**，转入条件 (b)。

**条件 (a)（论文层）**：论文中必须写成**明示的升级**而非静默偏离——"SOC 以连续状态逐场景精确携带；D10 要求的节点条件实现为：规划树条件在修正量 × 执行根条件在实测 SOC"。同时给出 (2) 的夜间量级作为"阶段 2 分档为空"的论据。

**条件 (b)（M5 层的廉价诊断，不引入迭代）**：待 M5 解出计划 $p$ 后（$p$ 已知，内生性即被绕过），做一次**诊断**——统计逐节点 SOC 的场景间离散度（6:00/12:00/18:00），与 SOC 区间宽（9600 kWh）及 3 等分档宽（3200 kWh）比较：
- 若阶段 3/4 的离散度 **< 1 个档宽**：D10 自带的免责条款"档数以不显著改变结果为限"在该数据上成立，偏离获得实证背书，写入论文即可；
- 若 **≥ 1 个档宽**：补一个**单次**灵敏度臂——用首解 $p$ 诱导的 SOC 分位切 3 档、与修正簇交叉重建节点、再解一次，报告计划 $p$ 是否移动。这里只需要一次单程迭代（不动点收敛非必需，因为只是灵敏度对照），成本可控。

**不由审计采纳的替代方案**：直接按 D10 字面做"节点 ×3 SOC 分档"。它在扩展型里要先把内生的 SOC 分区固定下来才能建树，即"先有 $p$ 才有档"，迫使 M5 做不动点迭代；而收益被 (2) 限制在阶段 3/4，与单次灵敏度臂给的信息量相当。故用 (b) 替代。

## 7. M5 消费接口（m4_tree 模块函数）

```python
scen = m4_tree.build_scenarios(e)          # 场景集合: A_hour(K,24), PV_slot(K,144), L_slot(K,144), w, idx
tree = m4_tree.build_tree(e, scen)         # 节点注册(nodes[lev][n]["members"]) + 父节点切分模型(model/child_map) + 叶标签 leaf
ex   = m4_tree.build_exec_ensemble(e, s, tree=tree)              # 默认: 全池; root_hour=C_adj(e,s)
exc  = m4_tree.build_exec_ensemble(e, s, tree=tree, cond=True)   # 硬条件臂: 场景 = 所落节点成员
nid  = m4_tree.route_node(tree, e, s)      # 已实现前缀 (G_1(e)…G_s(e)) → 阶段 s+1 节点号
G    = m4_tree.realized_prefix(e)          # 当日已实现修正量(恒等式已断言)
```
`build_exec_ensemble` 返回含 `node` / `cond` / `n_cond`，便于 M5 记录该日实际用了哪条臂。

规划 LP（M5）的形态预告：决策 = 计划 (a,b)^p（144 slot）+ 各节点 (a,b)（各自块 slot）；场景派生物理 = 逐场景 (g,c,curt,d,gap,SOC)（g,c,curt,gap 实时派生合法——逆变器级实时响应；购电量 = 结算量，节点共享）；目标 = E_ω[λ·购电 + 0.5λ·|q−p| + 5λ·gap]·Δt − ηλ₁₄₄·E[SOC^ω_144] + CYCLE_EPS；计划另附中心预测下的全天储能可行链（2.7-4）。偏差罚 aux 变量逐(节点×slot)。

## 8. 遗留与风险登记

- **阶段 4 叶薄**：占用 19.3/27、叶内 1–4 条路径——阶段 4 条件法则是 1–4 个历史日残差，样本薄但非退化（对比 200–500 场景下的空想精度）。M7 以池宽 {14,28,56} 扫描；56 池下叶占用翻倍。
- **重解内未来购电的场景派生**：执行重解中未来块的 (a,b) 为场景派生（内部估值设备，落盘即弃）——隐含"未来会话可见其块实现"的乐观近似，PLAN §2.4 的丢弃规则已默认；仅影响终值估计，二阶。
- **规划树 SOC 不作节点维**：**审计已采纳**，附两条条件（论文层明示升级；M5 层做一次节点 SOC 离散度诊断，必要时补单次灵敏度臂），见 §6。
- **执行重解条件集取全池**：一阶条件由中心 $C_{\text{adj}}(e,s)$ 承担，谱宽比实测 6:00=0.91/12:00=0.83，影响小；硬条件臂在 18:00 因池薄（66.7% 仅 1 条）会把晚间负载残差 std 253 kW 锁死为 0，有欠套保风险，故不作默认。M7 应把 `cond=True` 作为一条消融臂报告费用差异（见 §3）。
- **路由的稳定性**：`route_node` 依赖 k-means 质心，早停/种子改变会改变边界点归属（v1.1 修 refactor 时曾因种子变化使占用从 19.3 变 19.0，已恢复同种子）。M7 的池宽扫描需固定种子口径。
- **1 月供体对照**：M5 稳健性臂需要 1 月 PV 供体路径（w≡1 构造：ε0=A−F'_0、G_k=F'_k−F'_{k−1}，F_corr 全年可得）；负载侧 1 月无 EGD 预测，该臂复用主方案负载路径（对照只隔离 PV 供体效应）——M5 实现时落地。
- **冷启动单日补丁**：e=0 无树，M5 以 C_adj(e,0)/L_adj 的确定性 LP 生成计划并按实测结算（EEV 型单日）。
